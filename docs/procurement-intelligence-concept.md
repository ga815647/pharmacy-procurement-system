# 藥局採購情報系統｜原始構想

## 一、專案定位

建立一套「藥局採購情報系統」，包含兩個彼此獨立的子系統：

1. **三同藥品中盤比價系統**
2. **非藥品低價試賣雷達**

兩個子系統服務同一個目的：協助藥局找到更好的進貨機會。

但兩者的資料來源、使用方式與判斷邏輯不同，因此不預設共用商品主檔、查價介面、資料表或排序邏輯。

---

## 二、子系統一：三同藥品中盤比價

### 目的

使用者已經知道要找哪一類藥品，系統負責從不同中盤商取得報價，辨識三同藥品並比較採購成本。

### 三同判斷

- 同成分
- 同含量／劑量
- 同劑型

不同廠牌、製造商、藥證字號與包裝量，可以歸入同一個比較群組，但需保留差異供使用者判斷。

### 資料取得方式

依中盤商實際情況選擇：

- 網站爬蟲
- 登入後網頁擷取
- API
- Excel／CSV 匯入
- PDF 或其他報價檔匯入
- 人工輸入

爬蟲是資料取得方式之一，不預先排除。

### 核心流程

1. 從中盤商取得商品與報價資料。
2. 辨識成分、含量／劑量及劑型。
3. 將三同藥品歸入同一比較群組。
4. 保留廠牌、製造商、藥證字號與包裝差異。
5. 換算單位成本。
6. 顯示並排序各中盤商報價。

### 顯示資訊

- 中盤商
- 原始品名
- 成分
- 含量／劑量
- 劑型
- 廠牌或製造商
- 藥證字號
- 包裝規格
- 原始報價
- 換算後單位成本
- 庫存狀態
- 更新時間
- 原始來源

### 核心價值

> 正確辨識三同藥品，再比較不同來源與包裝的實際採購成本。

---

## 三、子系統二：非藥品低價試賣雷達

### 目的

主動搜尋全網低價與強折扣商品，協助藥局以少量進貨方式測試市場。

### 適用範圍

包括但不限於：

- 保健食品
- 尿布
- 奶粉
- 清潔用品
- 衛生用品
- 一般生活用品

### 資料來源

- 現有比價網
- 公開商城頁面
- 品牌官方商城
- 其他可取得價格、評論數及銷售資訊的網路來源

### 主要判斷資訊

- 商品或品牌的市場接受度
- 網路評論數
- 銷售量
- 目前可購入價格
- 相對常態價格的折扣力道
- 可購入數量
- 商品效期
- 是否適合少量試賣

規格仍需做基本辨識，避免把單瓶、多瓶組、不同容量或不同版本混為一談。

但此子系統的主要價值不是建立精密的規格資料庫，而是找出值得試賣的低價商品機會。

### 核心流程

1. 從比價網或公開網路來源取得商品資料。
2. 辨識基本商品與包裝差異。
3. 整理價格、評論數、銷售量及折扣資訊。
4. 找出全網低價與強折扣商品。
5. 供使用者選擇少量試賣。
6. 商品產生實際需求後，再決定後續補貨方式。

### 試賣原則

- 初期少量進貨。
- 未驗證需求前不大量囤貨。
- 第一批售出後再考慮補貨。
- 賣得動後，再比較網路低價與穩定供貨管道。
- 找不到穩定供貨源時，可定位為活動商品或售完為止。
- 折扣消失時，不勉強維持原商品。
- 穩定供貨代表補得到，不代表一定比較便宜。

### 核心價值

> 搜尋全網低價，找出值得用小量庫存測試的商品機會。

## 四、兩個子系統的差異

| 項目 | 三同藥品中盤比價 | 非藥品低價試賣雷達 |
|---|---|---|
| 使用模式 | 使用者主動搜尋特定藥品 | 系統主動發現商品機會 |
| 主要資料來源 | 藥品中盤商 | 比價網與公開網路來源 |
| 核心判斷 | 三同辨識 | 全網低價、折扣力道與市場熱度 |
| 主要輸出 | 哪個中盤商採購成本較低 | 哪些商品值得少量試賣 |
| 規格重要性 | 高 | 中等，避免基本誤配即可 |
| 穩定供貨 | 重要 | 初期不是必要條件 |
| 採購思維 | 已知要買什麼，再比較來源 | 先發現低價機會，再測試需求 |

## 五、專案整合方式

兩個子系統屬於同一個專案，但保持獨立開發。

```text
pharmacy-procurement-intelligence/
├─ drug-comparison/
│  └─ 三同藥品中盤比價
│
├─ retail-deal-radar/
│  └─ 非藥品低價試賣雷達
│
└─ shared/
   └─ 日後確認可共用的工具
```
