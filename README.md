# Pharmacy Procurement System

藥局採購、庫存與訂藥流程的規劃與實驗專案。

目前處於需求釐清與技術驗證階段。此 repository 先保存設計決策與原始構想，尚未決定最終實作方式，也不應放入真實藥價、供應商帳密、病患資料或其他敏感營運資料。

## 目標

建立一條可逐步落地的流程：

```text
採購情報／比價
    ↓
選擇採購品項
    ↓
建立訂藥單
    ↓
到貨驗收
    ↓
庫存、批號與效期
    ↓
會計資料匯出至 GnuCash
```

## 功能範圍

### 核心營運

- 商品與供應商資料
- 庫存量、批號與效期
- 最低庫存與補貨建議
- 訂藥單、部分到貨與驗收
- 採購價格歷史
- GnuCash 匯出介面

### 採購情報

- 三同藥品中盤比價
  - 同成分
  - 同含量／劑量
  - 同劑型
- 非藥品低價試賣雷達
- 中盤商 CSV、Excel、PDF、API 或網頁資料匯入

## 目前架構方向

優先評估以 **Odoo Inventory + Purchase** 作為庫存與採購核心，再以自訂模組實作藥局特有功能。

- Odoo：庫存、批號、效期、供應商、採購單、到貨與補貨
- 自訂模組：三同辨識、中盤商比價、低價試賣雷達
- GnuCash：會計與付款紀錄；初期採單向 CSV 匯出
- ChatGPT Sites：可用於操作介面原型，不預設能直接讀取藥局本機資料

是否採用 Odoo，仍需先以測試資料跑過「商品 → 訂貨 → 到貨 → 效期」流程後再決定。

## 設計原則

1. 不建立不必要的員工帳號流程；若採用 Odoo，可先以藥局共用操作帳號測試。
2. 不讓雲端網站直接讀寫 GnuCash 原始檔。
3. 庫存與會計各有唯一資料來源，避免雙向同步造成不一致。
4. 採購情報與核心庫存可獨立演進，但應透過訂藥單銜接。
5. 第一版先支援人工輸入與 CSV 匯入，自動爬蟲延後逐家驗證。
